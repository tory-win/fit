# 광고·커머스 연동 준비 (AdMob · 쿠팡 파트너스)

- 작성일: 2026-07-26
- 목적: 게이트 충전 수단 3종(M-2) 중 **광고**와 **쿠팡**을 실제로 켜기 위한 절차와 필요한 값 정리
- 원칙: 계정·키가 없으면 화면에서 `준비 중`을 유지한다. 누를 수 있는데 아무 일도 안 일어나는 버튼을 만들지 않는다.

## 0. AI 입어보기 수익 선행 정책 (2026-08-02)

- 아직 만들지 않은 착장 결과는 **보상형 광고 완료** 또는 **쿠팡 파트너스 링크 진입**이 확인된 뒤에만 AI 생성을 시작한다.
- 광고·쿠팡 확인 전에는 `generateTryon()`을 호출하지 않는다. 확인이 끝나면 사용자가 생성 버튼을 다시 누르지 않아도 즉시 시작한다.
- 이미 생성해 기기에 저장한 같은 결과는 다시 광고를 요구하지 않는다.
- 광고·쿠팡 확인 뒤 AI가 실패한 동일 요청은 다시 광고를 요구하지 않고 재시도한다. 다른 코디·다른 상품 조합은 새 확인이 필요하다.
- stage와 real 모두 고객 화면에 개발용 무료 통과 버튼을 두지 않는다. 두 환경 모두 같은 수익 선행 순서를 사용한다.

## 1. AdMob — 사용자가 해야 할 일

### 1.1 계정 만들기

1. [admob.google.com](https://admob.google.com) 접속 → 기존 구글 계정으로 로그인.
2. 국가·시간대·통화 설정. **통화는 나중에 못 바꾼다** — KRW로 정한다.
3. 결제 정보(수취 계좌·세금 정보) 입력. 수익이 최소 지급액에 도달해야 실제 송금되지만, 계정 확인은 미리 해두는 게 좋다.

### 1.2 앱 등록

1. AdMob 콘솔 → **앱 → 앱 추가**.
2. 플랫폼 **iOS** 선택 → "앱이 앱스토어에 등록되어 있나요?" → 지금은 **아니요**.
3. 앱 이름에 `입핏` 입력 → 추가.
4. 생성된 **앱 ID**를 받는다. 형식: `ca-app-pub-0000000000000000~1111111111` (물결 `~` 포함)

### 1.3 보상형 광고 단위 만들기

1. 해당 앱 → **광고 단위 → 광고 단위 추가** → **보상형** 선택.
2. 광고 단위 이름: `스타일패스 충전`.
3. 보상 설정: 항목 `pass`, 수량 `1`.
4. 생성된 **광고 단위 ID**를 받는다. 형식: `ca-app-pub-0000000000000000/2222222222` (슬래시 `/` 포함)

### 1.4 나에게 줄 값

```text
VITE_ADMOB_APP_ID=ca-app-pub-XXXXXXXXXXXXXXXX~YYYYYYYYYY
VITE_ADMOB_REWARDED_ID=ca-app-pub-XXXXXXXXXXXXXXXX/ZZZZZZZZZZ
```

이 두 값만 주면 실제 광고로 전환한다. 그전까지 내부적으로는 **구글 공식 테스트 광고 ID**로 동작하며, 운영 구분은 고객 화면에 표시하지 않는다.

### 1.5 앱스토어 출시 전 추가로 필요한 것

| 항목 | 내용 |
|---|---|
| `app-ads.txt` | 앱 스토어 등록 후, 개발자 홈페이지 루트에 게시해야 광고 단가가 정상화된다 |
| ATT(앱 추적 투명성) | 맞춤 광고를 쓰려면 `NSUserTrackingUsageDescription`과 추적 동의 팝업이 필요하다. 동의를 안 받으면 비맞춤 광고로만 돌아간다(수익 감소, 동작은 함) |
| SKAdNetwork | 광고주 성과 측정용 네트워크 ID 목록을 `Info.plist`에 넣어야 한다. 구글이 배포하는 목록을 그대로 복사한다 |
| 개인정보 처리방침 | 광고 SDK가 수집하는 항목을 `docs/개인정보처리방침.md` §8에 추가해야 한다 (현재 "연결돼 있지 않다"고 적혀 있음) |

**주의**: 심사 전에 실광고를 직접 클릭하면 계정이 정지될 수 있다. 개발 중에는 테스트 광고 또는 테스트 기기 등록만 쓴다.

## 2. 쿠팡 파트너스 — 링크 방식

사용자가 파트너스 API 키 대신 **발급된 트래킹 링크**를 줄 수 있는 상태다. 링크만으로도 게이트 연결은 가능하다.

### 2.1 필요한 값

```text
VITE_COUPANG_PARTNERS_URL=https://link.coupang.com/a/XXXXXX
```

### 2.2 지킬 것 (파트너스 정책)

- **수수료 고지 문구 필수**: "이 앱은 쿠팡 파트너스 활동의 일환으로 수수료를 제공받습니다." — 링크가 보이는 화면에 항상 노출한다.
- 쿠팡 링크 하나만 강제하지 않는다. 현재 게이트는 보상형 광고를 동등한 대안으로 함께 제공하고, 두 수단 모두 준비되지 않으면 생성 버튼을 활성화하지 않는다.
- 링크는 외부 브라우저/쿠팡 앱으로 연다(`@capacitor/app-launcher` 사용 중).

### 2.3 한계 (정직하게)

- 링크 방식은 **어떤 상품을 보여줄지 우리가 고를 수 없다.** 기획서 R-5의 "옷장 빈틈 아이템 우선 노출"은 파트너스 **API 키**가 있어야 가능하다.
- 그래서 지금 붙는 건 "쿠팡 둘러보고 스타일패스 열기"까지다. 부족 아이템 딥링크는 키를 받은 뒤 별도로 연결한다.

## 3. 앱에 들어간 구조

| 값 | 없을 때 | 있을 때 |
|---|---|---|
| `VITE_ADMOB_REWARDED_ID` | 구글 테스트 광고로 동작(고객 화면에는 운영 구분 미표기) | 실제 광고 게재 |
| `VITE_COUPANG_PARTNERS_URL` | 게이트에서 `준비 중` 유지 | `쿠팡 둘러보고 열기` 활성 + 수수료 고지 노출 |

- 값은 `app/.env.local`에 넣는다(저장소에 커밋하지 않는다).
- 웹(브라우저)에서는 광고 SDK가 동작하지 않는다. 그때는 `iPhone 앱에서 볼 수 있어요`로 안내한다.
- 네이티브 플러그인이므로 값을 바꾸거나 처음 붙일 때는 `npm run ios:linked` 재설치가 필요하다.

## 3.1 지금 붙어 있는 상태 (2026-07-26)

| 파일 | 역할 |
|---|---|
| `app/src/lib/ads.ts` | `@capacitor-community/admob` 초기화, 보상형 광고 표시. **보상 이벤트를 받은 경우에만** true |
| `app/src/lib/partners.ts` | 쿠팡 링크 검증(coupang.com https 만 통과), 수수료 고지 문구 |
| `app/src/App.tsx` GateSheet | 준비된 수단만 활성. stage/real 모두 같은 고객용 광고·쿠팡 선택 문구 사용 |
| `app/ios/App/App/Info.plist` | `GADApplicationIdentifier` = 구글 테스트 앱 ID. **실계정을 받으면 이 값을 바꾼다** |

패스 발급 사유는 내부 상태에서 구분하지만 고객 화면에는 개발·운영 사유 코드를 노출하지 않는다.

## 4. 남은 결정

- **구독(M-6)**: App Store IAP 등록과 RevenueCat 여부. 지금은 `준비 중` 유지.
- **배너·전면 광고(M-4·M-5)**: 보상형이 먼저 검증된 뒤에 붙인다. 아침 브리핑 화면에 배너를 넣을지는 U-9(예측 가능한 광고) 기준으로 다시 본다.
